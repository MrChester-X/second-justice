# «Второе мнение»

Прототип веб-интерфейса вспомогательной системы, предоставляющей судье
«второе мнение» при назначении наказания по уголовному делу.

Система проверяет проект судебного акта на соответствие санкции статьи
Особенной части УК РФ и правилам Общей части, оценивает основания
освобождения от уголовной ответственности и наказания по разделу IV УК РФ,
сопоставляет решение с практикой по схожим делам и формирует заключение.

**Система не принимает судебных решений и не заменяет судью.** Все выводы
носят справочно-аналитический характер и подлежат самостоятельной оценке
судьёй.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:3000.

Сборка и запуск в рабочем режиме:

```bash
npm run build
npm start
```

Требуется Node.js 20 или новее. Первая сборка обращается к Google Fonts за
шрифтами ParaType и встраивает их в сборку; дальнейшая работа проходит без
обращений к сети.

## Что можно посмотреть

1. `/` — вход. Аутентификации нет, вход выполняется в подготовленный профиль.
2. `/dashboard` — **личный кабинет**: профиль судьи, показатели проверок,
   реестр проектов судебных актов.
3. `/analysis/new` — загрузка документа. Можно перетащить свой `.docx` или
   `.pdf`, либо выбрать один из пяти демонстрационных материалов.
4. `/analysis/[id]` — **рабочая область анализа**, четыре вкладки:
   - *Параметры дела* — извлечённые параметры с пометкой достоверности
     извлечения и цитатами из документа; шкала санкции;
   - *Проверка соответствия* — проверки по группам, с расчётом и ссылками
     на практику Верховного Суда РФ;
   - *Аналогичные приговоры* — статистическая справка, гистограмма
     распределения, таблица приговоров с оценкой близости;
   - *Заключение* — готовый документ для печати.
5. `/database` — база судебных решений с фильтрами.
6. `/practice` — справочник практики Верховного Суда РФ.
7. `/reports` — архив заключений.
8. `/profile` — профиль и параметры проверки.

### Демонстрационные материалы

Пять подготовленных дел дают разные исходы проверки:

| Дело | Квалификация | Назначено | Результат |
|---|---|---|---|
| 1-241/2026 | ч. 1 ст. 158 УК РФ | исправительные работы 8 мес. | замечаний нет |
| 1-198/2026 | ч. 2 ст. 228 УК РФ | лишение свободы 2 г. 6 мес. | ниже низшего предела санкции без ст. 64 УК РФ |
| 1-77/2026 | ч. 4 ст. 111 УК РФ | лишение свободы 5 лет | в пределах санкции, но отклонение от практики на 1,8 σ |
| 1-312/2026 | ч. 1 ст. 116.1 УК РФ | обязательные работы 120 ч. | не обсуждены основания ст. 76 и 76.2 УК РФ |
| 1-155/2026 | ч. 3 ст. 264 УК РФ | лишение свободы 3 года | превышен предел ч. 2 ст. 62 УК РФ; не назначено дополнительное наказание |

### Живой пересчёт

На вкладке «Параметры дела» размер назначенного наказания редактируется.
Проверка пределов санкции, пределов правил Общей части, шкала и статистика
пересчитываются немедленно — расчёт выполняется по справочнику санкций, а не
берётся из заготовленных данных. Например, в деле 1-155/2026 достаточно
заменить 36 месяцев на 30, чтобы нарушение ч. 2 ст. 62 УК РФ было снято, а
проверки получили пометку «пересчитано».

## Переключение оформления

В шапке есть переключатель **«Суд / Арена»**. По умолчанию открывается
судебное оформление — именно его видит жюри при первом запуске; выбор
запоминается в браузере.

- **Суд** — светлая тема в духе ведомственных судебных систем.
- **Арена** — тёмное игровое оформление: графитовый фон с зернистостью,
  золотые обводки и угловые кронштейны панелей, скошенные углы кнопок,
  версальные заголовки, вердикты в зелёно-красной палитре.

Как это устроено: вся палитра вынесена в CSS-переменные, поэтому тема
переключается без единого изменения классов в компонентах, а игровое
оформление добавляет геометрию и свечения через восемь служебных классов
(`.panel`, `.btn`, `.th` и другие). Ассеты, гарнитуры и логотипы
компьютерных игр не используются — всё нарисовано средствами CSS.

Игровые названия получают только элементы оформления: навигация («Личный
кабинет» → «Профиль», «Новая проверка» → «Играть»), кнопка входа и главные
действия. Юридические формулировки, нормы, вердикты, названия вкладок и текст
заключения в обеих темах одинаковы: содержание судебного акта не может
зависеть от выбранной темы.

Две детали, на которые стоит обратить внимание при демонстрации:

- тема применяется до первой отрисовки страницы, поэтому тёмное оформление не
  моргает светлым при перезагрузке;
- **печать заключения всегда выполняется в судебной палитре**, даже если
  включена «Арена»: иначе документ ушёл бы на печать чёрной страницей.

## Границы прототипа

Реализована только клиентская часть. Бэкенда, моделей машинного обучения и
реальной базы судебных решений нет.

- **Извлечение параметров из произвольного документа не реализовано.**
  Загруженный файл проходит те же стадии обработки, но результат берётся из
  демонстрационных материалов; настоящими остаются имя, размер, число
  страниц и время загрузки файла.
- **Правовые данные справочные.** Тексты санкций, разъяснений и статистика
  собраны в плоских файлах `lib/data/` именно для того, чтобы их можно было
  вычитать без чтения кода интерфейса. Перед публичной демонстрацией
  формулировки норм подлежат сверке с действующими редакциями УК РФ и УПК РФ.
- **Выборка приговоров синтетическая.** Реальные судебные акты не
  использованы: суды, даты и размеры наказаний сгенерированы детерминированно
  из заданных распределений. В интерфейсе это указано.
- **Изложения позиций Верховного Суда РФ не являются цитатами.** Разделы
  разъяснений указаны по содержанию, а не номером пункта: прототип не должен
  создавать видимость дословного цитирования непроверенного текста.
- Экспорт заключения выполняется печатью средствами браузера
  («Сохранить как PDF»); файлового хранилища нет.

## Структура кода

```
app/
  page.tsx                       вход
  (workspace)/                   разделы под общей шапкой
    dashboard/                   личный кабинет
    analysis/new/                загрузка документа
    analysis/[id]/               рабочая область анализа
    database/ practice/ reports/ profile/
components/
  layout/                        шапка, знак системы, оговорка, заголовок раздела,
                                 переключатель оформления
  ui/primitives.tsx              панели, метки вердиктов, строки данных
  analysis/
    Workspace.tsx                вкладки и состояние анализа
    ParamsTab.tsx                извлечённые параметры
    ChecksTab.tsx                результаты проверок
    SimilarTab.tsx               статистика и аналогичные приговоры
    ConclusionTab.tsx            заключение для печати
    SanctionScale.tsx            шкала санкции
    PunishmentHistogram.tsx      распределение наказаний
lib/
  types.ts                       модель данных
  format.ts                      форматирование сроков, дат, числительных
  rules.ts                       живая проверка пределов наказания
  stats.ts                       медиана, квартили, отклонения, гистограмма
  api/analysis.ts                мок-слой: стадии обработки, сборка дел
  data/
    uk-sanctions.ts              санкции статей УК РФ
    practice.ts                  разъяснения и обзоры Верховного Суда РФ
    sentences.ts                 база судебных решений
    cases.ts                     пять демонстрационных дел
    judge.ts                     профиль пользователя
  store/session.ts               реестр дел сеанса
  theme/                         константы, состояние и подписи оформления
docs/
  stack.md                       состав ПО и лицензии
  superpowers/specs/             проектная документация
```

Мок-слой изолирован в `lib/api/`: функции асинхронные и отвечают с
задержкой, компоненты об отсутствии сервера не знают. Замена мока на
реальные вызовы затрагивает только этот каталог.

## Публикация на GitHub Pages

Сайт выкладывается статически: сервера нет, `npm run build` собирает готовые
HTML-файлы в `out/`.

Что нужно сделать один раз в репозитории на GitHub: **Settings → Pages →
Build and deployment → Source: GitHub Actions**. После этого каждый push в
`main` запускает `.github/workflows/deploy.yml`, который собирает сайт и
публикует его. Адрес — `https://<владелец>.github.io/<репозиторий>/`.

Префикс пути (`/<репозиторий>/`) подставляется на сборке из переменной
`NEXT_PUBLIC_BASE_PATH`; в CI её значение выдаёт `actions/configure-pages`,
поэтому переименование репозитория ничего не ломает. Локальная сборка без
этой переменной рассчитана на корень домена.

Проверить сборку так, как её увидит GitHub Pages:

```bash
NEXT_PUBLIC_BASE_PATH=/<репозиторий> npm run build
```

Два следствия статической выкладки, заметные в коде:

- Страницы дел собираются заранее по идентификаторам демонстрационных дел
  (`generateStaticParams`), поэтому у них остаются адреса вида
  `/analysis/1-241-2026/`.
- Дело, загруженное пользователем, получает идентификатор уже в браузере, и
  страницы для него не существует: оно открывается общим маршрутом
  `/analysis/case/?id=...`. Выбор адреса — в `lib/routes.ts`.

## Интерфейс

Интерфейс, подсказки, отчёты и заключения выполнены на русском языке.
Оформление по умолчанию — светлая тема в духе ведомственных судебных
информационных систем; вторая тема описана выше. Контрасты текста в тёмной
теме проверены и соответствуют уровню AA. Оговорка о вспомогательном
характере системы выведена на каждом экране и включена в печатное
заключение.
